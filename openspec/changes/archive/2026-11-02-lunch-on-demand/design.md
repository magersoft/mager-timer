# Design

## Context

Сейчас обед зашит в график: `Schedule.lunchStart` + `lunchMinutes = 60` превращаются в `DayPlan.lunchStart/lunchEnd` по часам (не сдвигаются от фактического начала). От этого интервала зависят фаза `.lunch` (`Engine.phase`), правила перерывов (`breakAllowed`, `plannedBreaks`, сброс отсчёта на `lunchEnd` в `tickBreaks`), строки меню и лента (`Snapshot`: `isLunch`, «Обед, перерывы с …», «Следующий перерыв после обеда»). Деньги обед не трогает: `DayPlan.earned` растёт по активному времени, обед в нём не вычитается. Паузы уже устроены как интервалы в `DayRecord.pauses` (последняя может быть открыта) — обед повторяет эту форму, но с другим смыслом. Мотивация — в proposal.md, поведение — в specs.

## Goals / Non-Goals

**Goals:**
- Обед — состояние дня, которое включает и выключает пользователь; расписание только для напоминания и окна подсказок.
- Ядро остаётся чистым: всё время приходит параметром `now`, автозакрытие обеда вычисляется, а не ставится таймером.
- Старые настройки и записи дней читаются без миграции.

**Non-Goals:**
- Месячная статистика обедов (отложенная идея; сейчас только сохраняем интервалы).
- Автоопределение обеда по активности за маком.
- Настраиваемый лимит обеда.

## Decisions

**1. Обед как интервалы в `DayRecord.lunches`, отдельно от пауз.**
Новый тип `Lunch { start: Date; end: Date? }` (форма как у `Pause`), поле `lunches: [Lunch]` через `decodeIfPresent ?? []`. Альтернатива — пауза с флагом «обед»: экономит тип, но пауза сдвигает конец и останавливает деньги, и каждое место, которое считает паузы (`activeTime`, `duration`, `plan(…)`, ленту, недоработку), пришлось бы учить их различать. Отдельное поле ничего из этого не задевает: деньги и конец от обедов не зависят по построению.

**2. Открытый обед разрешается лениво: эффективный конец = min(now, начало + остаток лимита, сдвинутый конец дня).**
`DayRecord.resolvedLunches(at:planEnd:)` по аналогии с `resolvedPauses`. Лимит считается по уже закрытым обедам дня. На тике трекер записывает `end`, как только эффективный конец наступил раньше `now` (лимит или конец графика), — запись в истории всегда закрыта честным моментом, даже если приложение не тикало (сон мака). `finalize` в полночь использует ту же функцию с `now` = полночь. Альтернатива — хранить «плановый конец» при включении: ломается, если до этого день сдвинула пауза.

**3. `DayPlan` теряет `lunchStart/lunchEnd`, получает `lunches: [DateInterval]` и `lunchSince: Date?`.**
Фаза `.lunch` = есть открытый обед и `now < plan.end`. Окно обеда по графику (для уведомления и кнопки на экране перерыва) — отдельное вычисление в `Engine` от `Schedule.lunchStart` по часам, `DayPlan` его не хранит, чтобы никто случайно не стал по нему считать фазу.

**4. `Schedule`: поле `lunchStart` остаётся (тот же JSON-ключ), смысл — время напоминания; добавляется `lunchReminder: Bool` (`decodeIfPresent ?? true`).**
Удаляются `lunchMinutes`/`lunchEnd` из `Schedule`; лимит 60 мин живёт как константа обеда. Проверка `lunchOutsideDay` заменяется на «напоминание в [start, end)» с новым текстом ошибки. Переименовывать ключ не стали: тогда пришлось бы читать оба ключа, а смысл легко передать комментарием и подписью в UI.

**5. Действия трекера: `startLunch(now:)`, `endLunch(now:)`; изменения в существующих.**
- `startLunch`: только в фазе `.working` (через `runningPlan`, без открытой паузы и открытого обеда) и при остатке лимита > 0.
- `endLunch`: закрывает открытый обед в `now`; если длина ≥ длины перерыва — `breaks.restart(at: now)` (тот же `rest(since:now:)`).
- `pause` — запрещена при открытом обеде; `finishEarly` — сначала закрывает обед в `now`; `resetStart` — очищает `lunches`.
- Автозакрытие по лимиту в `tick` тоже вызывает правило «обед ≥ перерыва = отдых» с моментом эффективного конца.

**6. Напоминание — событие `Event.lunchTime` через `notifyOnce("lunch", deliver:)`.**
Ключ помечается на первом тике, когда `now ≥ время напоминания` в начатом дне; `deliver` = обед сейчас доступен (то же условие, что у кнопки) и `now` внутри окна обеда по графику (мак проспал всё окно — не шлём). Помечаем независимо от `deliver`, поэтому после снятия паузы уведомление не догоняет — как требует спека. Выключенное напоминание — событие не создаётся. `Notifier` получает категорию с действием «Ухожу на обед» → `AppModel.startLunch()`.

**7. Перерывы.**
- `breakAllowed` больше не знает про обед: остаётся только правило 15 минут до конца графика.
- `breaksRunning`/`tickBreaks`: фаза `.lunch` — перерывы не идут; сброс отсчёта на `lunchEnd` удаляется (его заменяет решение 5).
- `plannedBreaks(plan)` считает разрывами паузы и взятые обеды плана. Подсказка в настройках вызывает его с планом, в который подставлен предполагаемый обед `[lunchStart, +60)` — отдельный параметр, чтобы день и подсказка не путались.
- Кнопка на экране перерыва: `DaySnapshot.BreakScreen` отдаёт флаг `offersLunch` = перерыв активен, напоминание включено, момент начала перерыва внутри окна обеда по графику, обед доступен. Действие «Ухожу на обед» снимает перерыв без учёта (`activeSince = nil`, ни `taken`, ни `skipped`) и вызывает `startLunch`.

**8. Snapshot и view.**
`HourSlot.isLunch` считается по `plan.lunches`; лента красит реальные интервалы. Новые действия `Action.lunch` и `Action.endLunch`, подпись кнопки — `Today.lunchButton`; строка «🍜 Обед · осталось N мин». Формулировки — в `Snapshot`, view только показывает. Строка перерывов на обеде — «Обед, перерывы после него»; ветка «Следующий перерыв после обеда» удаляется.

## Risks / Trade-offs

- [Плановое N перерывов меняется в течение дня, когда берётся обед] → так уже работают паузы; подсказка в настройках считает типичный день с часом обеда, чтобы число не выглядело завышенным.
- [Забытый «Вернулся» съедает лимит] → осознанно (решение пользователя): на деньги не влияет, страдает только статистика.
- [Тесты завязаны на обед 13:00–14:00 по расписанию (`BreakTests`, `DayStartTests`, `ModelsTests`)] → переписываются в рамках задач, ожидаемые числа пересчитаны в спеках (например, подсказка 07:00–15:00 → 6 перерывов).
- [Удаление `DayPlan.lunchStart/lunchEnd` ломает компиляцию во многих местах сразу] → порядок задач: модель и движок с тестами, затем трекер, перерывы, snapshot, UI.

## Migration Plan

Без миграции данных: `Schedule.lunchStart` читается как время напоминания, `lunchReminder` по умолчанию `true`, `DayRecord.lunches` по умолчанию пуст. Откат — предыдущая сборка читает те же файлы (лишние поля игнорируются `Codable`).
