# Design

## Context

Репозиторий пустой (только OpenSpec). Среда: macOS 26, Xcode 26.6, Swift 6.3. Приложение личное: без подписи Developer ID, без App Store и песочницы. Требования — в `specs/`, мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**
- Вся логика расчётов — чистые функции от `(настройки, календарь, курсы, история, now)`, покрытые unit-тестами без UI и сети.
- Состояние дня восстанавливается из времени и истории, а не из накопленного в памяти таймера: перезапуск, сон и смена часового пояса не ломают суммы.
- Ноль сторонних зависимостей.

**Non-Goals:**
- Мультиплатформенность, iCloud-синхронизация, локализация кроме русского.
- Точный учёт активности до секунды — достаточно опроса раз в несколько секунд.

## Decisions

### D1. Структура: SwiftPM-пакет `MotivateCore` + тонкое app-приложение
- `MotivateCore` (library, без AppKit/SwiftUI): модели, календарь, ставка, фазы, переработка, цель, форматирование сумм. Тесты — `swift test`, быстро и без Xcode UI.
- `MagerMotivate` (SwiftPM executable target, SwiftUI, default isolation MainActor): `MenuBarExtra(.window)`, окно настроек, сервисы платформы (уведомления, активность, автозапуск, сеть).
- *Альтернатива:* один app target — отвергнута, логику тогда тестировать сложнее и медленнее.
- Сборка `.app` — скриптом `scripts/build-app.sh`: `swift build -c release`, сборка бандла с `Info.plist` (`LSUIElement = YES`, bundle id `com.magersoft.MagerMotivate`), ad-hoc подпись `codesign -s -`. Бандл нужен для уведомлений и `SMAppService`.
- *Альтернатива:* `.xcodeproj` — отвергнут: XcodeGen/Tuist не установлены, ручной `project.pbxproj` хрупок; пакет и так открывается в Xcode.
- Хранилище (`Storage`) и парсеры календаря/курсов — в `MotivateCore` (только Foundation), чтобы покрыть их тестами; сетевые запросы — в приложении.

### D2. Модель времени: вычисление, а не накопление
- Заработок дня = `rate × clamp(now − start, 0, plannedDuration)`. Таймер раз в секунду только перерисовывает.
- Переработка — единственное накапливаемое значение; хранится как `OvertimeState { mode: auto|manual, closedAt?, lastActivityAt?, manualSince?, accumulated }` в файле дня и пересчитывается при каждом тике из `lastActivityAt` и `now`, поэтому выдерживает перезапуск.
- Обработка сна: подписка на `NSWorkspace.didWakeNotification` → немедленный тик и догоняющие уведомления.
- *Альтернатива:* инкрементальный счётчик в памяти — отвергнут: дрейф и потеря при перезапуске.

### D3. Ставка через норму часов месяца
`rate(day) = Σ toRUB(salary, fx(day)) / normHours(month)`, где `normHours` = Σ 8 ч за обычный рабочий день календаря + 7 ч за сокращённый. Отпуска на норму не влияют. Валюта отображения применяется только при форматировании.

### D4. Производственный календарь
- Источник: `https://isdayoff.ru/api/getdata?year=YYYY&pre=1&covid=0` — строка на каждый день года (`0` рабочий, `1` выходной, `2` сокращённый).
- Кэш: `calendar-YYYY.json` в Application Support; загрузка при старте и раз в сутки, если нет текущего или следующего года (следующий — с 1 декабря).
- Фолбэк без данных: пн–пт рабочие, флаг `approximate` для предупреждения в меню.
- *Альтернатива:* встроенный в бандл календарь — отвергнут: устаревает и требует пересборки.

### D5. Курсы ЦБ
- Источник: `https://www.cbr-xml-daily.ru/daily_json.js` (USD, EUR → RUB, с полем `Date`).
- Фиксация: при первом расчёте рабочего дня курс записывается в `DayRecord.fx`; повторно не перечитывается.
- Последний полученный курс хранится в `fx-latest.json` как фолбэк. Нет курса для валюты → оклад исключается, флаг предупреждения.

### D6. Хранилище
- `~/Library/Application Support/MagerMotivate/`:
  - `settings.json` — `Settings { incomes[], displayCurrency, schedule, vacations[], goal?, launchAtLogin }`;
  - `history/YYYY-MM.json` — массив `DayRecord { date, earnedRUB, rateRUB, fx, plannedHours, overtime, dayOff }` по месяцам;
  - кэши календаря и курсов.
- Запись атомарная (`Data.write(options: .atomic)`), кодирование `JSONEncoder` с ISO-датами.
- Сегодняшний `DayRecord` обновляется при смене фазы, действиях пользователя и раз в минуту; прошлые дни неизменяемы.
- Догон пропущенных дней (из `app-settings`) выполняется при запуске: от последней записи до вчера.
- *Альтернатива:* SwiftData — отвергнута: для десятков записей избыточна и усложняет тесты ядра.

### D7. Активность пользователя
- Простой: `CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType: .null)` — не требует разрешения Accessibility.
- Сон/блокировка: `NSWorkspace` `willSleep/didWake`, `DistributedNotificationCenter` `com.apple.screenIsLocked/Unlocked` → простой.
- Опрос раз в 5 с только в фазе «после графика».

### D8. Уведомления
- `UNUserNotificationCenter`, категория `END_OF_DAY` с действиями `FINISHED` и `STILL_WORKING`; делегат передаёт их в тот же обработчик, что и меню.
- Начало и конец дня планируются заранее как `UNCalendarNotificationTrigger` на сегодня; при пробуждении проверяется флаг «отправлено» в `DayRecord`, чтобы не дублировать и догнать пропущенное.
- Напоминания о переработке — немедленные уведомления по достижении каждого полного часа.

### D9. Автозапуск
`SMAppService.mainApp.register()/unregister()`; при первом запуске — `register()`, если настройка включена (по умолчанию).

### D10. UI
- `MenuBarExtra` со стилем `.window` — нужны прогресс-бары и кастомная вёрстка; цвет заголовка при переработке задаётся через `Text` с `foregroundStyle(.red)`.
- Один `@Observable AppModel` на главном акторе держит снимок `DaySnapshot`, вычисленный ядром на каждом тике.

## Risks / Trade-offs

- [isdayoff.ru или cbr-xml-daily.ru недоступны/изменят формат] → кэш, фолбэк, предупреждение в меню; парсеры покрыты тестами на сохранённых фикстурах.
- [Цвет текста в menubar может игнорироваться системой для шаблонного рендера] → проверить на macOS 26; запасной вариант — `NSStatusItem` с attributed title.
- [Без подписи Gatekeeper ругается при первом запуске] → сборка локально через Xcode, запуск из `~/Applications`; приемлемо для личного использования.
- [Догон пропущенных дней засчитывает полный день, даже если пользователь болел] → это прямое следствие «время идёт по графику»; отгул можно поставить задним числом — допустимая доработка позже.
- [Смена часового пояса / перевод часов] → все времена графика трактуются в текущем часовом поясе системы; день определяется по локальной дате.

## Open Questions
